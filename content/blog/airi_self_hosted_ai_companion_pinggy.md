<a href="https://github.com/moeru-ai/airi" target="_blank">AIRI</a> is sitting at #3 on GitHub's daily trending page as I'm writing this, with north of 42,000 stars and a release cut just six days ago. The pitch, straight from the repository description, is a mouthful: "self hosted, you-owned AI companion, a container of souls of waifu, cyber livings to bring them into our worlds, wishing to achieve Neuro-sama's altitude." Strip out the flavor text and what's left is genuinely interesting: an open-source, browser-native AI companion that talks back in real time, plays Minecraft and Factorio alongside you, and runs its inference on your own GPU through WebGPU instead of a vendor's API.

If you've followed <a href="https://en.wikipedia.org/wiki/Neuro-sama" target="_blank">Neuro-sama</a>, the AI VTuber that's been quietly one of the most-watched streamers on Twitch, you know the shape of what people want here: a persistent character with a voice, a personality, and the ability to actually do things in a game world, not just answer chat questions. AIRI is the open-source community's attempt at that, and unlike Neuro-sama it's something you can clone and run tonight.

## What AIRI actually does

AIRI (built by a hobby group called Moeru AI) breaks its system into four parts that map roughly onto what a companion needs to feel alive:

- **Brain**: LLM integration and game-playing logic for Minecraft, Factorio, and (work in progress) Kerbal Space Program.
- **Ears**: audio input, Discord and browser audio capture, client-side speech recognition, and voice activity detection.
- **Mouth**: text-to-speech across multiple providers - ElevenLabs, Azure, OpenAI, Kokoro (a local option), and Alibaba's TTS.
- **Body**: VRM and Live2D model rendering, with auto-blinking, gaze tracking, and idle animation.

The part that makes this more than another chatbot wrapper is where the compute happens. Stage Web, the browser build, runs the inference pipeline through WebGPU for GPU acceleration and WebAssembly for the surrounding logic, including an in-browser DuckDB instance (compiled to WASM) for local memory storage. Nothing about a Stage Web session has to touch a server you don't control, beyond whichever LLM API you point it at - and even that's optional, since AIRI supports local backends like Ollama, vLLM, and SGLang alongside the 25+ hosted providers wired up through its `xsai` adapter (OpenAI, Anthropic, DeepSeek, Gemini, Groq, Mistral, and more).

Game integration is the feature that actually differentiates this from a voice assistant. Minecraft support uses <a href="https://github.com/PrismarineJS/mineflayer" target="_blank">Mineflayer</a>, the venerable Node.js bot library, so the companion can respond to what's happening in the world and take actions, not just narrate. Factorio support lives in a separate repo, <a href="https://github.com/moeru-ai/airi-factorio" target="_blank">airi-factorio</a>, and currently combines an RCON wrapper for headless server control with a computer-vision-plus-LLM approach (YOLO for object detection, an LLM for planning) as a proof of concept for pure vision-based play.

## Why this is landing now

Two trends are colliding here, and either one alone would explain some interest, but together they explain a 42,000-star repo. The first is the AI VTuber phenomenon itself: Neuro-sama has spent the last couple of years proving there's a real audience for an AI character with a persistent personality that plays games and banters with chat, and every open-source community eventually tries to reproduce the thing that's captivating people just out of reach. The second is the much broader local-AI-companion backlash: as cloud AI companion apps increasingly get scrutinized over what happens to your conversation data, "self-hosted and you-owned" has become a genuine selling point rather than a niche preference. AIRI's own framing leans into this hard - its whole premise is that the character's "soul" (its memory, its config, its identity) belongs to you, running on your hardware, not rented from someone else's cloud.

## Getting it running

The browser build is the fastest path in:

```bash
git clone https://github.com/moeru-ai/airi
cd airi
pnpm i
pnpm dev
```

That starts Vite's dev server (the project's `dev` script is literally `vite --host`, so it's already bound to every network interface, not just loopback) at `http://localhost:5173`. Open it, pick a language, click "setup with your provider," paste in an API key for whichever LLM you're using, and you have a talking companion.

If you'd rather not build from source, there are native installers: `winget install MoeruAI.AIRI` on Windows, `brew install --cask airi` on macOS, or `scoop install airi/airi` if you're a Scoop user. The desktop build (Stage Tamagotchi) is an Electron/Tauri app that adds native CUDA and Metal acceleration through HuggingFace's Candle framework, which matters if you're running a local model and want it fast.

## The part that trips people up: it only really works on localhost

Here's the thing nobody mentions until they try it from a second device: AIRI's voice chat needs `getUserMedia()` to grab your microphone, and modern browsers only grant microphone access on a <a href="https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts" target="_blank">secure context</a> - HTTPS, or the special-cased `localhost` origin. WebGPU has the same restriction. So `pnpm dev` working perfectly on the machine you started it on tells you nothing about whether it'll work anywhere else.

Try it from your phone over Wi-Fi at `http://192.168.1.42:5173` and the mic permission prompt never fires; the browser silently refuses because plain HTTP over a LAN address isn't a secure context. AIRI's own docs run into this too - to get their Stage Pocket mobile client talking to a desktop instance wirelessly, the documented fix is starting the desktop app with `sudo pnpm dev:tamagotchi` so it can bind a secure WebSocket locally, which works but means running your AI companion as root just to get a padlock icon.

## Reaching AIRI from your phone with Pinggy

A tunnel solves this more directly than the root-and-self-signed-cert route: instead of making your LAN connection secure, you skip it entirely and connect over a real HTTPS URL from the start. Leave `pnpm dev` running in one terminal, open a second, and run:

{{< ssh_command >}}
"{\"cli\":{\"windows\":{\"ps\":\"./pinggy.exe -p 443 -R0:localhost:5173 free.pinggy.io\",\"cmd\":\"./pinggy.exe -p 443 -R0:localhost:5173 free.pinggy.io\"},\"linux\":{\"ps\":\"./pinggy -p 443 -R0:localhost:5173 free.pinggy.io\",\"cmd\":\"./pinggy -p 443 -R0:localhost:5173 free.pinggy.io\"}},\"ssh\":{\"windows\":{\"ps\":\"ssh -p 443 -R0:localhost:5173 free.pinggy.io\",\"cmd\":\"ssh -p 443 -R0:localhost:5173 free.pinggy.io\"},\"linux\":{\"ps\":\"ssh -p 443 -R0:localhost:5173 free.pinggy.io\",\"cmd\":\"ssh -p 443 -R0:localhost:5173 free.pinggy.io\"}}}"
{{</ ssh_command >}}

Pinggy prints back a public HTTPS URL, something like `https://a1b2c3.a.pinggy.link`. Open that on your phone and the browser sees a genuine HTTPS origin - the mic permission prompt fires normally, WebGPU initializes, and if AIRI's PWA manifest is being served (Stage Web is PWA-enabled), "Add to Home Screen" works too, none of which happen over a bare LAN IP. The compute is still happening back on your laptop; the tunnel is just carrying the WebSocket and HTTP traffic between your phone's browser and your GPU.

This is also the quickest way to let someone else meet your companion without walking them through a local build. Send a teammate or a friend the pinggy.link URL while your session is live, and they get the same Stage Web interface you're looking at, avatar and all.

Since AIRI keeps conversation memory and provider API keys client-side, don't leave the tunnel open indefinitely. Add HTTP basic auth for anything beyond a quick demo:

```bash
ssh -p 443 -R0:localhost:5173 a.pinggy.io -t "b:friend:temporarypass"
```

That's enough to stop a guessable link from being scraped while you're using it, without setting up real authentication in AIRI itself.

## What this is and isn't good for

**Good for:** testing voice chat and the PWA install flow on your actual phone instead of fighting Chrome's insecure-context restrictions, demoing AIRI to someone without making them clone and build it, or checking in on a Minecraft session your companion is playing while you're away from your desk.

**Not good for:** a permanent public deployment. AIRI's Stage Web build has no concept of separate user accounts - anyone with the URL and your basic auth credentials gets the same session, memory, and provider access you have. Treat the tunnel as a temporary bridge for testing and demos, not a way to host a companion for the public.

## Conclusion

AIRI's trending spike is a decent read on where two different audiences are pointing right now: people who want an AI VTuber companion like Neuro-sama, and people who want their AI tools to run on hardware they own instead of a subscription behind an API key. Getting it running locally is a `pnpm dev` away. Getting it onto a second device with working voice chat is the part that actually needs a bit of networking know-how - and a Pinggy tunnel turns that into one SSH command instead of a `sudo` flag and a certificate warning.
