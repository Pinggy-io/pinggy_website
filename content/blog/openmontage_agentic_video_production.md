## The core idea

Video production has two expensive parts: time and expertise. Cloud AI video tools - Sora, Runway, Kling - have made expertise cheaper, but they are still black boxes. You upload a prompt, get a clip back, and have no control over the intermediate steps.

OpenMontage takes a different approach. Rather than being a product you subscribe to, it is a toolkit your AI coding assistant operates. The directory is full of Markdown skill files that teach your assistant video production knowledge, YAML pipeline manifests that describe the production stages, Python tools for every step from web research to subtitle generation, and a React-based composition engine powered by <a href="https://remotion.dev" target="_blank">Remotion</a>.

The key sentence from the README: "There is no code orchestrator. Your AI coding assistant IS the orchestrator."

This means Claude Code, Cursor, GitHub Copilot, Windsurf, or Codex becomes the director. OpenMontage is the crew.

## The five production stages

Every video follows the same pipeline regardless of which of the 12 templates you pick:

**Research → Script → Assets → Edit → Compose**

**Research** is treated as a genuine first step, not an afterthought. Before writing a word of narration, your assistant searches YouTube, Reddit, Hacker News, news sites, and academic sources to collect audience questions, trending angles, and visual references. The output is a structured research brief that feeds every stage downstream. If you skip this stage, the script is guessing about what the audience actually wants to know.

**Script** turns the brief into narration text, scene descriptions, visual cues, and timing estimates. Your assistant is making decisions here - which facts to include, how long each scene runs, which images or clips support each point.

**Assets** is where it calls out to external APIs and local tools: video generation, image generation, TTS for narration, music. Each call goes to whichever provider is configured in `.env` for that asset type, falling back to free options when no key is set.

**Edit** handles the media processing - trimming, syncing narration to video, adding subtitles, mixing audio tracks. This runs locally via FFmpeg.

**Compose** is the final stage - building the React scene tree in Remotion and rendering either a preview or a final MP4.

Built-in quality checks run at two points: before composing (to block renders that would violate the delivery spec) and after rendering (ffprobe + audio analysis to catch sync or encoding problems).

## 12 production pipelines

The `pipeline_defs/` directory has twelve YAML manifests, each describing a specific video type:

| Pipeline | What it produces |
|---|---|
| **Animated Explainer** | Data-driven walkthroughs using React scenes in Remotion |
| **Animation** | Character and abstract animation via video generation APIs |
| **Avatar Spokesperson** | Talking-head narration using HeyGen or similar |
| **Cinematic** | Trailer-style output with Runway Gen-4 or Kling |
| **Clip Factory** | Batch short-form output for social media |
| **Documentary Montage** | Real footage from stock archives and public domain sources |
| **Hybrid** | Mixed AI-generated and stock footage |
| **Localization & Dub** | Re-narrate existing video in 700+ languages via Google TTS |
| **Podcast Repurpose** | Turn audio into subtitle-driven clips |
| **Screen Demo** | Screen recording with narration overlay |
| **Talking Head** | Webcam-style AI avatar presenter |
| **Character Animation** | Rigged character sequences |

Each pipeline YAML is human-readable. The stage sequence, provider choices, and asset constraints are all editable without touching Python - which makes it practical to fork a pipeline and tune it for a specific use case.

The composition engine is chosen at the proposal stage and locked for the run. Remotion (React-based) is the default for data-driven explainers and anything using the existing scene stack. HyperFrames (HTML/CSS/GSAP) is preferred for motion-graphics-heavy briefs.

## What it costs

OpenMontage lists 14 video generation providers - Kling, Runway Gen-4, Google Veo 3, Grok Imagine, MiniMax, HeyGen, plus local options like WAN 2.1, Hunyuan, CogVideo, and LTX-Video. It also has 10 image generation integrations and four TTS options.

Most of the good ones are paid. But there is a genuinely usable zero-cost path:

- **Narration:** <a href="https://github.com/rhasspy/piper" target="_blank">Piper TTS</a> (free, local, offline, installed automatically by `make setup`)
- **Footage:** Pexels, Pixabay, Archive.org, NASA footage archive, Wikimedia Commons
- **Composition:** Remotion (MIT licensed)
- **Post-production:** FFmpeg

The README shows demo video production costs ranging from $0.15 to $3. The low end is achievable with Piper TTS and stock footage. The high end kicks in when you use Runway Gen-4 or Kling for AI-generated clips, ElevenLabs for voice cloning, or Suno for original music.

For a 60-second animated explainer explaining a developer tool, you can go from prompt to rendered MP4 spending nothing if you are comfortable with Piper's voice quality (it is decent, not broadcast-grade).

## Getting set up

Prerequisites: Python 3.10+, FFmpeg, Node.js 18+.

```bash
git clone https://github.com/calesthio/OpenMontage.git
cd OpenMontage
make setup
```

`make setup` installs Python requirements, runs `npm install` in the `remotion-composer/` subdirectory, installs Piper TTS, and copies `.env.example` to `.env`. Open `.env` and add keys for whichever paid providers you want to use. Leave everything blank for the free-only path.

Then open the `OpenMontage/` directory in your AI coding assistant of choice and start a conversation:

```
Make me a 90-second documentary montage about the history of Hacker News,
using public domain footage where possible. Budget: $0 (free sources only).
```

Your assistant will read the skill files in `skills/`, pick the Documentary Montage pipeline, generate a research brief, show you a proposal to approve, then begin executing tools stage by stage. You can intervene at any approval step to redirect the creative direction.

## Sharing previews with Pinggy

Remotion Studio - the preview player for video compositions - runs as a local web server at `localhost:3000`. When the assistant finishes building a composition, you get an interactive scrubber in the browser where you can step through frames before committing to a full render.

If you are running OpenMontage on a remote machine (a GPU-equipped VPS, a home server you SSH into, or a Colab-style cloud notebook), that preview server is only accessible locally. Same situation if you want a client or collaborator to review a draft before you render the final file - they cannot reach `localhost:3000` on your machine.

Pinggy solves this with one command:

```bash
ssh -p 443 -R0:localhost:3000 free.pinggy.io
```

Pinggy prints a public HTTPS URL - something like `https://abc123.a.pinggy.link` - that forwards to your Remotion Studio instance. Share that URL with your client. They can scrub through the composition in their browser, see exactly how the scenes cut together, and give feedback before you spend time (or API credits) on a final render.

The tunnel lasts as long as the SSH session stays open. For a persistent URL across sessions, [Pinggy's paid plans](https://pinggy.io/#prices) let you set a fixed subdomain so your preview link does not change between working sessions.

If you want to avoid the SSH command, the <a href="https://pypi.org/project/pinggy/" target="_blank">Pinggy Python SDK</a> can be scripted directly:

```python
import pinggy
token = pinggy.start_tunnel(forwardto="localhost:3000")
print(f"Preview URL: {token.url}")
```

## The honest tradeoffs

**No web UI.** Everything goes through your AI coding assistant. If you want to trigger a pipeline without opening Claude Code or Cursor, you would have to call the Python tools directly from the command line. This is a real barrier for non-technical collaborators who want to use it without a coding environment.

**AGPL license.** The pipeline code is GNU AGPLv3. Good for the open-source ecosystem, awkward if you are building a commercial product on top of OpenMontage without intending to open-source your changes. The Remotion composer is MIT, so the front-end component is clean - but the backend is not.

**Heavy dependency chain.** Python 3.10+, Node.js 18+, FFmpeg, Piper TTS, and optionally a GPU for local video generation models. These are all standard tools but setup on a fresh machine takes 10-15 minutes.

**Output quality is API-dependent.** With the free tier, Piper TTS sounds robotic on complex sentences and Pexels footage may not match your specific visual needs. The gap between free-tier output and paid-API output is noticeable.

**Research stage is a weak point.** Web search results vary by topic, and if the research brief gets bad sources or misreads community sentiment, everything downstream inherits those mistakes. Worth reviewing the brief before approving the script stage.

**Early project.** OpenMontage launched yesterday. Expect sharp edges, sparse documentation in some areas, and breaking changes in pipeline YAML schemas as the project matures.

## Who should try this

If you produce technical tutorials, product explainers, or developer-focused content and you already live in Claude Code or Cursor, OpenMontage is worth an afternoon. The zero-cost path is real, the pipeline architecture is clean, and the ability to review compositions interactively in Remotion Studio before rendering is a genuine time-saver.

If you want a no-code video tool with a dashboard and a credit system, look at <a href="https://runwayml.com" target="_blank">Runway</a>, <a href="https://www.heygen.com" target="_blank">HeyGen</a>, or <a href="https://www.descript.com" target="_blank">Descript</a>. OpenMontage assumes you are comfortable reading YAML pipeline definitions and running shell commands.

If you are building a video generation pipeline into a larger product, the architecture here - readable YAML manifests, modular Python tools, Markdown skill files - is worth studying even if you end up writing something custom. Just budget for the AGPL license implications before building on top of it.

The 14k stars and 3,500-in-a-day trajectory suggest this project has real momentum. Getting in early means rough edges, but also a responsive maintainer and a chance to shape what the pipelines look like as they mature.
