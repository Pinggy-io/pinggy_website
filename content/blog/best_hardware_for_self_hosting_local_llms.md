A 16 GB graphics card can hold the 9.3 GB Qwen3 14B download with room for a chat. The same card can't hold the 20 GB Qwen3 32B download. That's the first buying decision for a local LLM: which exact model do you want to keep on the GPU, and how much conversation history does it need? A faster card with the same memory capacity leaves you with the same fit problem.

{{% tldr %}}

- **For one person running 8B to 14B models**, start with hardware you already own. An 8 GB card can handle an 8B model at four bits with a modest context. For a new desktop build, the RTX 5060 Ti **16 GB** leaves room for a larger model or a longer conversation.
- **For a dense 32B model at four bits**, consider a 24 GB or 32 GB card. For **70B**, start by pricing a 64 GB or larger unified-memory system, or a workstation GPU with at least 48 GB. A 48 GB card can be tight once you add long prompts or a second user.
- **For 405B**, Ollama's Llama 3.1 Q4_K_M download alone is 243 GB. A 512 GB M5 Ultra Mac Studio has room for the model and a cache on one machine. A sharded CUDA setup is another option if you already own the hardware or need its serving software.

{{% /tldr %}}

## How much memory does your model need?

These are published Ollama downloads, rounded in decimal GB. Each link identifies the exact quantization behind the figure. The last column is a starting point for a single session. The practical ceiling depends on your prompt length and inference engine.

| Checkpoint | Q4_K_M download | Hardware to consider |
| --- | ---: | --- |
| <a href="https://ollama.com/library/qwen3:8b" target="_blank">Qwen3 8B</a> | 5.2 GB | Existing 8 GB GPU for short chats |
| <a href="https://ollama.com/library/qwen3:14b" target="_blank">Qwen3 14B</a> | 9.3 GB | 12 GB for modest context, 16 GB for more headroom |
| <a href="https://ollama.com/library/qwen3:32b" target="_blank">Qwen3 32B</a> | 20 GB | 24 GB GPU for short context, 32 GB for more room |
| <a href="https://ollama.com/library/llama3.3:70b" target="_blank">Llama 3.3 70B</a> | 43 GB | 48 GB dedicated or 64 GB and up in a shared-memory machine |
| <a href="https://ollama.com/library/llama3.1:405b-instruct-q4_K_M" target="_blank">Llama 3.1 405B Instruct</a> | 243 GB | High-memory workstation or a model split across multiple devices |

Weights are only the first allocation. The key/value (KV) cache holds attention state for earlier tokens. A longer conversation grows that cache, and simultaneous sessions need additional cache space. The engine also needs work buffers. On a Mac or an integrated AMD system, leave room for the OS and your other applications in the same pool.

For a rough sense of precision costs, 70 billion weights at two bytes each (BF16) occupy about **140 GB** before overhead. At one byte each, the raw weight budget is about **70 GB**. Two 24 GB cards give you 48 GB in aggregate: worth investigating for the 43 GB four-bit checkpoint, too small for a fully GPU-resident eight-bit copy. For a mixture-of-experts model, use the size of the whole checkpoint for capacity planning even if only a fraction of its parameters are active on each token.

## What tokens per second actually measures

When you're chatting alone with a dense model, generating the next token usually involves reading most of its weights again. Once they fit in GPU-accessible memory, bandwidth often limits how fast the reply streams. As a rough upper bound, reading 43 GB once per token over a 273 GB/s memory bus gives about **6.3 tokens/s**. That's arithmetic for a dense, single-stream decode. Kernel overhead, cache traffic and other users of the bus can lower the observed rate.

Reading a long prompt is a different job. The GPU can process many input tokens together, so compute capacity matters more. Record **time to first token** for document work, **output tokens/s** for interactive chat, and **aggregate throughput plus per-user latency** for a shared server. Compare the same model, quantization, prompt length, software and number of users.

## Large unified-memory systems

A shared-memory desktop is attractive when a 43 GB model would otherwise spill out of a discrete GPU onto the CPU. Choose the memory configuration first. A product's starting price usually buys less RAM than its maximum specification.

| System | Unified memory | Published bandwidth | When it makes sense |
| --- | --- | --- | --- |
| Mac Studio M5 Max | 36 GB base, up to 128 GB | 460 or 614 GB/s, by chip | A Mac for daily work and local inference. Choose 64 GB or more for the 43 GB model. |
| Mac Studio M5 Ultra | 96 GB base, up to 512 GB | 1.2 TB/s | Large models on one machine using Metal or MLX. The 512 GB configuration leaves working room around a 243 GB checkpoint. |
| AMD Ryzen AI Halo, Max+ PRO 495 | Up to 192 GB, up to 160 GB available to graphics | 273 GB/s | A compact x86 Windows or Linux machine for models that exceed discrete VRAM. |
| ASUS ProArt GR1X, RTX Spark | 64 or 128 GB | 300 GB/s | Windows on Arm with an integrated NVIDIA Blackwell GPU. Check that your runtime has an Arm build. |
| NVIDIA DGX Spark, GB10 | 64 GB on select partner systems or 128 GB | 273 GB/s | Linux on Arm with CUDA, NVIDIA containers and a supported path to distributed inference. |

**Mac Studio.** Apple lists the US starting prices at **$2,499 for M5 Max** and **$5,499 for M5 Ultra**. The 512 GB option requires the 36-core CPU / 80-core GPU M5 Ultra and costs extra. If you already have an M4 Max or M3 Ultra that fits your model, benchmark your own prompts before upgrading. <a href="https://www.apple.com/mac-studio/specs/" target="_blank">Apple configuration matrix</a> · <a href="https://www.apple.com/newsroom/2026/08/apple-introduces-new-mac-studio-with-m5-max-and-m5-ultra/" target="_blank">US launch pricing</a>.

**Ryzen AI Halo.** A 128 GB Ryzen AI Max+ 395 is still a useful comparison when pricing a 70B system. The PRO 495 raises the available graphics allocation to 160 GB on the 192 GB configuration. A roughly 140 GB BF16 checkpoint leaves a much tighter margin there than its four-bit counterpart. AMD also offers Project Zenith, a preconfigured Windows 11 developer environment, on the PRO 495 Halo. <a href="https://www.amd.com/en/blogs/2026/project-zenith-comes-to-amd-ryzen-ai-halo-ready-to-code.html" target="_blank">AMD's November Halo availability and specifications</a>.

**RTX Spark.** ASUS announced US availability of the ProArt GR1X for November 18. In a hands-on test using Qwen3.8 27B in LM Studio, the 128 GB GR1X generated **25.63 tokens/s** on a writing task, against **20.76 tokens/s** on a 128 GB Ryzen AI Max 395 mini PC. Time to first token was **0.32 s versus 1.10 s**. The reviewer listed $4,499 as the US starting price and $6,999 for the tested GR1X. The article doesn't specify the quantization, so use those results for that workload only. <a href="https://press.asus.com/news/press-releases/asus-announces-availability-proart-gr1x-rtx-spark-mini-pc" target="_blank">ASUS availability</a> · <a href="https://www.asus.com/displays-desktops/mini-pcs/proart-mini-pc-series/proart-gr1x-mini-pc/techspec/" target="_blank">ASUS specifications</a> · <a href="https://www.tomsguide.com/computing/mini-pcs/nvidia-rtx-spark-mini-pc-review-benchmarks-vs-amd" target="_blank">Tom's Guide test and configuration prices</a>.

**DGX Spark.** Budget separately for each node. At NVIDIA's published $4,699 Founders Edition MSRP, two 128 GB units come to **$9,398** before tax and networking. Two nodes can connect directly through their ConnectX-7 ports with a supported QSFP cable. To run one model that exceeds a single node’s memory, the engine must distribute it across the nodes. For a larger deployment, NVIDIA documents an eight-node, 1 TB cluster running the full GLM 5.3 NVFP4 model. At concurrency one it reports 31 generated tokens/s using MTP3 speculative decoding. That figure describes eight machines running a specific model. <a href="https://forums.developer.nvidia.com/t/2-23-2026-price-change-announcement/361713" target="_blank">Founders Edition pricing</a> · <a href="https://www.nvidia.com/en-us/products/workstations/dgx-spark/" target="_blank">DGX Spark connectivity</a> · <a href="https://developer.nvidia.com/blog/running-frontier-class-ai-models-across-8-nvidia-dgx-spark-nodes" target="_blank">NVIDIA's eight-node measurements</a>.

## Enterprise GPUs for a shared service

For a serving team, compare how many sessions each GPU sustains at your required context length and response time. NVIDIA lists **80 GB and 3.35 TB/s** for H100 SXM, **141 GB and 4.8 TB/s** for H200 SXM, and **180 GB and up to 8 TB/s** for B200 SXM. An H100 can fit the 43 GB Llama checkpoint on one accelerator. The H200 gives that same checkpoint more room for active requests and their caches. Keeping a 243 GB checkpoint entirely in GPU memory requires multiple accelerators in all three cases. <a href="https://docs.nvidia.com/enterprise-reference-architectures/hgx-ai-factory-h100-h200-b200/latest/components.html" target="_blank">NVIDIA HGX reference specifications</a>.

## Storage, RAM, and multi-GPU

**Storage.** Keep enough free SSD space for every quantization you intend to test. The 20 GB and 43 GB models in the table already use about 63 GB together. A faster SSD helps a cold start. Once the model is resident, changing the SSD has little effect on generation speed.

**System RAM.** If you offload layers to the CPU, budget for those weights, the runtime and your other applications. On integrated systems the GPU allocation comes from the same physical memory the OS needs. Swapping model pages to disk during a reply is a reason to shorten context or choose a smaller checkpoint.

**Multiple GPUs.** A runtime can place different layers on different cards or split operations across them. Each card still needs its own buffers. Link speed, available PCIe lanes and the runtime's partitioning strategy affect the result. For a multi-user service, a second copy of a smaller model on another GPU can also serve a separate queue if each copy fits independently.

## Cloud vs. owning hardware

Compare the cost of completing the same workload at the latency your users need. Suppose a workstation costs **$3,000** and a comparable rental is **$1.50 per active hour**. If the workstation costs **$0.15 per active hour** for electricity, its purchase price breaks even at about **2,222 active hours**: 3,000 divided by (1.50 minus 0.15). At 40 hours a month that's over four years. These are example inputs. Add idle power, storage, maintenance and rental fees that apply to your setup.

For production, rent the candidate GPU briefly and replay representative requests. A data-center card that handles several requests at once may cost less per completed job even if its hourly rate is higher. Record the number of concurrent users, prompt and output lengths, and the slowest response your application can tolerate.

## Getting started with Ollama

Install <a href="https://ollama.com/download" target="_blank">Ollama for your operating system</a>. On a 16 GB card, try this workload first:

```sh
ollama run qwen3:14b --verbose "Explain how a DNS cache works in three sentences."
ollama ps
```

*Check the model tag before budgeting GPU memory. The 9.3 GB shown here covers the download. A running session also needs memory for the context cache and work buffers. Screenshot from {{< link href="https://ollama.com/library/qwen3:14b" >}}Ollama{{< /link >}}, November 2026.*

Run the same prompt again with the model warm. Ollama's verbose statistics separate prompt evaluation from output generation. In `ollama ps`, the `PROCESSOR` column shows whether the model loaded entirely on the GPU or split across CPU and GPU. Try a document close to the length you'll actually use before drawing conclusions from the short prompt. For a larger system, repeat with `llama3.3:70b`. <a href="https://docs.ollama.com/faq" target="_blank">Ollama's memory and GPU checks</a>.

For a chat frontend on Docker Desktop, run Open WebUI alongside the host Ollama installation:

```bash
docker run -d -p 127.0.0.1:3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui \
  ghcr.io/open-webui/open-webui:main
```

That gives you a ChatGPT-like interface at `localhost:3000`. Our guide on {{< link href="/blog/best_open_source_alternatives_to_chatgpt/" >}}open-source ChatGPT alternatives{{< /link >}} covers more frontend options if you want something beyond the basics.
